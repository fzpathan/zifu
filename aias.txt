SESSION BEHAVIOR RULES

1. Full session memory and recall
The orchestrator must retain the complete conversation and work history 
for the duration of the session (not just the last few turns). At any 
point, if the user asks what has been done so far, it must be able to 
accurately summarize: configs/sheets built, decisions confirmed, and 
pending items — pulled from actual session history, not inferred or 
guessed.

2. Plan → Execute (4/4) only on explicit trigger
The agent must never automatically generate a Plan and move into 
Executing (4/4) on its own initiative. A plan may only be created and 
executed once the groundwork has been explicitly laid — i.e. the user 
has confirmed the requirements/summary for that piece of work. Do not 
auto-start planning as a default reaction to a new request.

3. Close out each Plan → Execute cycle fully before the next
Once a Plan → Execute (4/4) cycle completes all its steps, it must be 
marked closed and not resurface, re-trigger, or partially re-run in a 
later plan. Any additional instructions given mid-execution during 
that cycle must be resolved and completed within that same cycle — 
they must not carry over or bleed into the next plan's execution, 
since that causes confusion about what's still pending versus already 
handled.

4. Full read/search access to configs and master schedule
The agent must have read access to all existing config files and the 
master schedule file, and must be able to search within them to answer 
user questions directly (e.g. "what's the FileDateSelection for X 
config" should be answerable by searching the actual files, not by 
guessing or relying on memory of an earlier conversation).

5. Session-start flow
At the start of every session, the first thing the agent asks is 
whether this session is for a NEW config or UPDATING an existing one.

- If NEW: ask for the control type and which schema to follow 
  (Comp or QA, as the generic base). Once both are provided, create an 
  empty Excel file using the appropriate template — do not create the 
  file before both control type and schema are confirmed.

- If UPDATE: pull the latest version of that config along with its 
  associated schedule file first. Then proceed based on what has 
  actually changed (compare against the latest version), rather than 
  rebuilding from scratch.

6. Default to conversational mode; read full context before every reply
The agent's default mode is peer-to-peer conversation — answering 
questions, discussing, clarifying — not repeatedly generating and 
executing plans at every step. It should only move into Plan → Execute 
mode when the user explicitly confirms they're satisfied with the 
summary and says to proceed/build. Before responding to anything, the 
agent must first read the entire session conversation so its answer is 
grounded in full context, not just the latest message.
