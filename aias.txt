Here they are in build order — implement and test each before moving to the next, since later ones depend on earlier ones working.

**Step 1 — Fix the data-loss bug (do this first)**
```
In the tool that writes sheets to the Excel workbook, change the write 
logic so it checks if the target workbook file already exists before 
writing. If it exists, load it with openpyxl.load_workbook() and add 
the new sheet using wb.create_sheet(). If it doesn't exist yet, create 
a new Workbook and remove the default blank sheet. Never re-instantiate 
a blank workbook when the file already exists — always load, then 
append, then save back to the same path.
```

**Step 2 — Add the manifest (the actual "memory")**
```
Add a persistent JSON manifest file per config-build session, saved 
next to the output workbook (e.g. same folder, named 
<workbook_name>_manifest.json). It should track: workbook_path, 
sheets_done (list of completed sheet names), and schema_notes (a short 
description of the schema/pattern used for each sheet). Every tool 
that writes a sheet must read this manifest before acting and update 
it immediately after a successful write. Tie the manifest to the 
session ID so it persists across app restarts, not just within one 
chat window.
```

**Step 3 — Ground each step in the real file**
```
Add a step that runs automatically before any new sheet is generated: 
open the current workbook file, list existing sheet names, row counts, 
and key schema fields for each, and return this as a short summary. 
Feed this summary into the context for the sheet-generation step 
instead of relying on the model's recollection of earlier turns.
```

**Step 4 — Pass full context into every step**
```
Change the orchestrator so that when generating a new sheet, it passes 
the full manifest and the latest file-inspection summary into the 
sub-agent or tool call — not just the user's newest instruction. If 
sub-agents are dispatched independently per sheet, explicitly inject 
this context into each dispatch call rather than letting sub-agents 
infer prior work from nothing.
```

**Step 5 — Confirm-before-assume gate**
```
Add a rule to the orchestrator: before generating a new sheet, if the 
schema/pattern for it isn't explicitly stated in the user's current 
request, state in one line the assumed pattern (based on prior sheets 
in the manifest) and wait for the user to confirm before proceeding. 
If the user's request already specifies the schema, skip confirmation 
and proceed directly. Once confirmed, save the pattern into the 
manifest's schema_notes so it isn't re-asked for future sheets that 
follow the same pattern.
```

**Step 6 — Tone**
```
Update the system prompt with these tone rules: respond in first 
person, active voice, like a colleague giving a short status update. 
Never use phrases like "I have successfully completed the task of...", 
"Please note that...", or narrate steps before doing them ("I will now 
proceed to..."). State results directly, e.g. "Added GCAL_HBUS — same 
T-4 pattern as HBEU, 3 rows, validation passed." Keep routine 
confirmations to one line, assumption-check questions short and 
direct, and avoid stacked hedging language. Include 3-4 example 
good/bad response pairs in the system prompt covering: finishing a 
sheet, flagging an assumption, and hitting an error.
```

Test steps 1–2 together first (that's what stops sheets from disappearing) before moving on — the rest builds on top of that working.
